NOTES / FINDINGS
----------------
N1  Qwen/vLLM narration is MOCK-BY-DEFAULT, not real Qwen.
    get_bridge() returns a ColabQwenBridge whenever /opt/anaconda3/envs/venv/bin/colab
    exists (it does), but the Colab session "lora-train" is NOT running:
      colab ls -> "No active sessions found"; bridge.health_check() -> False
    => /api/qwen and /ws/stream narration return the placeholder
       "Vision narrator: connecting to Colab vLLM daemon..." forever.
    qa2 "narration updated" therefore only proves the PLACEHOLDER rendered and the
    "Waiting for AI analysis" state cleared - it does NOT prove real Qwen output.
    Related bug: ws_stream.py:44 and qwen.py:16 do `get_bridge() or MockQwenInference()`;
    get_bridge() is truthy even when the daemon is down, so the mock path is never
    taken -> placeholder narration instead of mock narration.
    Fix options: (a) run the Colab session + vLLM daemon (colab/start_vllm_daemon.sh),
    (b) make get_bridge() return None when health_check() fails -> then mock fallback
    narrates realistically.

N2  ws.py:36-37 `finally: await websocket.close()` raises
    RuntimeError('Cannot call "send" once a close message has been sent.') when the
    client disconnects first (observed in /tmp/fsd-backend.log for the WS probe).
    Endpoint still completes; error is logged by uvicorn, not swallowed (cf. silent
    swallow at ws.py:34 except Exception: pass). Recommended guard:
    try-block close. Minor.

N3  ws_error observed in driver probe (page-side): a single WS error event on the
    Node WebSocket client after the frontend demo WS and probe WS both close.
    No impact on demo; consistent with N2 server-side close race.

N4  fps finding reinforces F2 CQ-07: demo stream is ~1.3-2.2fps, not 30fps.
    Plan's 30fps success criterion requires STREAM_INTERVAL <= 0.033s (and/or async
    inference decoupling). Not a regression; design constant.
